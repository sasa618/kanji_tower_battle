# 漢字タワーバトル（試作）

宙に浮いた平らなステージに，漢字を物理演算で積むゲームの試作である．C++ で，2D の剛体の物理演算から自作している．下の表の組み合わせの字どうしが触れると，合体して別の字になり，字が 1 つでもステージから落ちたら終わりとなる．基本の字は 木・日・月・人・口・水・火 の 7 つで，合体してできる字は次の 17 個である．合体してできた字の中では，人は亻（人偏）や彳（行人偏），水は氵（さんずい）の形になる．

| 組み合わせ | できる字 |
|---|---|
| 木 + 木 | 林 |
| 木 + 林 | 森 |
| 日 + 月 | 明 |
| 月 + 月 | 朋 |
| 日 + 日 | 昌 |
| 人 + 木 | 休（亻） |
| 口 + 口 | 回 |
| 口 + 木 | 困 |
| 水 + 日 | 沓 |
| 火 + 火 | 炎 |
| 人 + 回 | 徊（彳） |
| 水 + 木 | 沐（氵） |
| 口 + 昌 | 唱 |
| 日 + 木 | 東 |
| 日 + 昌 | 晶 |
| 林 + 火 | 焚 |
| 人 + 口 | 囚 |

## 作った動機

インターンの復習として，アルゴリズムを調べながら自分の手で実装してみるために作った．その上で，実装したものを新しいゲームとして落とし込むことを目的としている．

## ゲーム性

スコアは，ステージの上に積んだ字の総画数である．補助として，塔の高さと字数も数えている．合体しても画数の合計はほぼ変わらない（木 4 画 + 木 4 画 = 林 8 画など．徊は 1 画増え，沐は 1 画減る）．一方で，2 字分の場所が 1 字分になるため，複雑な漢字を作るほど，同じ場所に積める画数の密度が上がる．このため，限られたスペースの中でどれだけ多くの画数を積めるかが重要になり，複雑な字を作るほど得をする．

## 遊び方

ステージの横幅は，基本の字 5 つ分（400px）である．落とす字の候補として，どれも違う字が 3 つランダムに出るので，1～3 キーで落とす字を選ぶ．選んだ字が塔の上で待つので，動かしてから落とす．落とした後は操作できず，字を 1 つ落とすたびに候補を選び直す．落とした字が着いて全部が止まると（長くても約 2 秒で），選んでいる候補の字が塔の上に出る．

スコア（総画数）と，塔の高さ（何字分か）・字数は画面の右上に出る．落とした後まだ着いていない字は数えない．字が 1 つでもステージから落ちたら（重心がステージの下の面より下に行ったら）ゲームオーバーとなり，その時の値が最終スコアとして画面の真ん中の帯に出る．塔が高くなると，画面は上へスクロールする．画面の右には，合体の例として 木 + 木 → 林，木 + 林 → 森，人 + 木 → 休（亻），水 + 木 → 沐（氵），日 + 月 → 明，口 + 口 → 回 だけを出している．偏になる字は，どの偏になるかを括弧で添えている．

| キー | 操作 |
|---|---|
| Space | 開始 / 停止 |
| ← → | 落とす前の字を 1 マス（8px）動かす |
| ↑ | 90 度回す |
| ↓ | 落とす |
| 1～3 | 3 つの候補から落とす字を選ぶ（位置と角度はそのまま） |
| R | リスタート（最初からにして，すぐに動かす） |
| E | 字のエディタを開く |
| B | 漢字図鑑を開く |

## 字のエディタ

基本の字 7 つと偏 3 つ（亻・彳・氵）の形を，10×10 マスの上で作ることができる．形を変えると，合体してできる字も含めてすぐに作り直され，画面の下の「仕上がり」に出る．閉じるとゲームは最初からになる．

| 操作 | 内容 |
|---|---|
| ドラッグ | 画を引く（0.1 マス刻み） |
| 端の点をドラッグ | 画の端を動かす（始点は青，終点は赤） |
| クリック | 画を選ぶ |
| Delete / BackSpace | 選んだ画を消す |
| Q / W | 選んだ画の始点 / 終点の端の作り方を変える（そのまま → 伸ばす → 縮める → 平らな足） |
| Z | 元に戻す（1 回分） |
| T / G | 右の枠のステージに，まっすぐ / 傾けて落とし，立つか倒れるかを見る |
| ← → | 編集する形を切り替える |
| S | `kanji_data.txt` に保存する |
| E / Esc | ゲームに戻る |

ただし，合体してできる字の部品が多すぎる（24 を超える）形や，画が無い形，短すぎる画（0.3 マス未満）は作れないようにしている．

## 漢字図鑑

漢字No.（No.1 木 ～ No.24 囚）ごとに，ゲームで落とした回数と，合体して作った回数を記録している．画面の上には字の一覧が出て，一度でも落としたか作った字は形が，まだの字は「？」が出る．矢印キーかクリックで字を選ぶと，下の欄にその字の読み・意味・熟語・作り方が出て，合体してできる字には作った回数も出る．落とした回数は，見つけたかどうかを決めるためだけに使い，画面には出さない．読みはカタカナが音読み，ひらがなが訓読みであり，読み・意味・熟語は主なものだけを載せている．まだ見つけていない字は，説明も出さない．記録は `kanji_collection.txt` に残るので，次に起動しても消えない．

## 文字の形の作り方

字は 10×10 マス（1 マス 8px）の方眼の上に，画ごとに中心線の始点と終点を書いて表している（`kanji.cpp` の `kBuiltinStrokes`，またはデータファイル）．画 1 本は太さ 1.25 マス（10px）の凸四角形にして物体の部品 1 つとし，1 字が 1 つの物体になる．質量・重心・慣性モーメントは，物理演算の `CalculateMass` がそのまま部品から求める．

角や交わる所では，片方の画の端を太さの半分だけ伸ばすか縮めて，隙間も重なりも作らないようにしている．部品が重なると，重なった所の質量を二重に数えてしまうためである．この作り方であれば，画の太さを変えても継ぎ目は合ったままになる．併せて，地面に着く払いの先は水平に切って平らな足にし，どの字も足の高さを 10 マス目にそろえている．斜めの角のままでは片足から着いて回され，人や水が倒れていたためである．

合体してできる字も 1 字の大きさ（80px 角）にしている．具体的には，材料の形（字そのものか，亻・彳・氵 の偏）の画の中心線を，合体後の字の中で決めた範囲に縮めて並べる．画の太さは変えないので，どの字も同じ太さで描かれる．合体の表（`kanji.cpp` の `kRecipes`）が，形の作り方と合体の決まりを兼ねている．ただし，東は画を直接決めた専用の形を使い，晶は昌ではなく日を 3 つ並べている．

合体の条件は，合体の表にある組み合わせの 2 字が触れることである．同じ組み合わせで作れる字がいくつかあるときは，底が平らで幅の広い，転がりにくい形を選ぶ方針である．合体するときは 2 字を消して 1 字を入れ，重心は 2 字の重心の平均（質量で重みづけ），向きは 2 字の向きを質量で重みづけした平均とする．速度は，2 字をひとまとまりの物体とみなしたときの重心の速度を引き継ぎ，角速度は 0 にする．2 字分の場所が 1 字分になるので，周りに隙間ができ，上に載っていた字は下がる．

## 仕組み

### 当たり判定

当たり判定では，物体どうしの重なりを見つけて押し出し，接触点を集めている．1 フレーム（1/60 秒）を 2 つのサブステップに分け，その各サブステップで次の 4 段階を行う．N は物体（字とステージ）の数，n は部品の頂点の数（画 1 本の部品は 4 つ），C は接触点の数である．

| 段階 | 使ったアルゴリズム | 計算量 |
|---|---|---|
| 1. 調べる組の絞り込み | 平面走査（外接長方形の上の端の高さの順に並べる），並べ替えは挿入ソート | 総当たりの O(N²) に対し，ほぼ O(N + 縦の範囲が重なる組の数) |
| 2. 重なりの判定 | 外接長方形の判定のあと，部品（凸多角形）の組ごとに分離軸判定 | 部品 1 組あたり O((n_A + n_B)²) |
| 3. 押し出しと接触点 | 分離軸判定で影の重なりがいちばん小さかった軸の向きへ押し出し，接触面の頂点から接触点を 1 点か 2 点取る | 部品 1 組あたり O(n_A + n_B) |
| 4. 前回の接触点との対応づけ | 同じ順に並んだ 2 つの列を先頭から同時になぞる（尺取り法） | 総当たりの O(C²) に対し，O(C) |

組の絞り込みでは，物体の番号を外接長方形の上の端の高さの順に並べ，上にある物体から順に，自分の下の端より上から始まる物体だけを相手にしている．字は下から上へ積み上がっていくため，横ではなく縦の軸で並べている．並べ替えには挿入ソートを使っている．物体は 1 フレームの間にほとんど入れ替わらず，前回の並びがほぼそのまま使えるため，ずらす回数は少ない．見つけた組は物体の番号の順に並べ直してから押し出しに回しており，総当たりのときと同じ順に処理されるため，結果は変わらない．

重なりの判定には分離軸判定を用いている．字は，画 1 本を凸四角形の部品とし，その組み合わせで 1 つの物体（凹んだ物体）として表しているため，部品の組ごとに分離軸判定をそのまま使うことができる．併せて，影の重なりがいちばん小さい軸とその幅を覚えておき，押し出す向きと深さとして使っている（英語圏では minimum translation vector と呼ばれる）．このため，押し出す向きを求めるための追加の計算はいらない．

押し出しでは，深さから許容貫通誤差（0.5px）を引いた分だけ，軽い方が多く動くように 2 つの物体を動かす．めり込みを少し残すことで，次のフレームでも接触点が取れ，支える力が安定する．

前回の接触点との対応づけは，ウォームスタート（前のフレームのインパルスを最初に与える）に使っている．接触点には「物体 a の通し番号，物体 b の通し番号，部品の組と点の番号」で番号を付けており，今回も前回もこの順に並んで作られる．そこで，前回の側の位置を今回の接触点に追いつくまで進めるだけで，同じ接触点を見つけている．物体の番号ではなく通し番号を使うのは，合体で字を消すと番号が詰まるためである．

合体の判定にも，当たり判定で集めた接触点を使っている．同じ組の接触点は続けて並んでいるため，組ごとに 1 回だけ調べる．2 字が合体するかは，字の種類 2 つから行の番号を直接引ける表（24×24）で調べている．

### 衝突応答

集めた接触点には，逐次インパルス法でインパルス（力積）を与え，近づく速度を打ち消している．全接触点について 10 回反復して解き，インパルスの合計が 0 以上になるように制限している．併せて，摩擦（上限は摩擦係数 0.8 × 垂直抗力），回転，ウォームスタートを入れている．跳ね返りは入れていない（反発係数 0）．

### 実時間を使った処理

物理演算は，常に同じ刻み（1/60 秒）で進めている．過ぎた時間を `QueryPerformanceCounter` で測ってためておき，1 フレーム分たまるごとにゲームを 1 フレーム進める．たまるまでは `Sleep(1)` で待ち，待つ時間の細かさを `timeBeginPeriod(1)` で 1 ミリ秒にしている．

## 検討したこと

合体の条件は，当初「決まった並び方（左右か上下に 1 字分ずれて並ぶ）で，どちらもまっすぐ立っていること」としていた．しかし，触れさえすれば合体する方が遊びやすいと考えて，並び方とまっすぐの条件は外した．

人の形は，一度，両脚をほぼ頂点から出す左右対称の形にした．ほかの字の上に落としたときの倒れにくさは上がったものの，「Λ」に見えて人らしくないため，却下とした．現在は右の払いを左の払いの途中（3 分の 1 ほど下）から出す形にしており，倒れにくさは左右対称の形と同じであった（ほかの字の上に落とす 42 通りのうち 25 通りで倒れない）．

口 + 木 は，当初は杏にしていた．傾けて落とす試験では，杏は 0.6 ラジアン（約 34 度）傾けると倒れ，0.9 ラジアンでは 1 回転以上転がった一方で，困は起き上がって立ったため，困に変えた．

合体したときの角速度は，当初は 2 字の角運動量を新しい字の慣性モーメントで割っていた．ところが，合体した字は 1 字の大きさに縮んで軽く，回りにくさも小さくなるため，林の上に木を落とすと森が毎秒 15 ラジアンで回っていた．そこで，2 字全体の慣性モーメントで割るように直し，毎秒 0.4 ラジアンほどに収まった．しかし，まっすぐ落として合体させても，少しずれて当たっただけで回り出し，不自然に見えた．このため，角運動量を引き継ぐ方法は却下とし，合体した字の角速度は 0 にした．

東は，当初は木を縦に伸ばして日を重ねて作った．しかし，木の払いが日の中を通って日の穴がふさがり，東に見えなかったため，画を直接決めた形に変えた．

点数は，当初「字を 1 つ積むと 10，合体するとできた字の画数 × 10」としていた．しかし，限られたスペースにどれだけ多くの画数を積めるかを競う遊びにするため，ステージの上の総画数をスコアにした．
